# WhaleDeck 分阶段开发任务

本文把 [FEATURES.md](FEATURES.md) 拆为可执行任务。顺序按依赖和风险排列，不代表工期承诺。所有任务在 `dev` 或功能分支完成，`master` 只接收可部署版本。

## 1. 当前基线与状态

截至 2026-10-12，M0、M1、M2、M3 与 P1 的主体已部署并完成多项真实依赖验收；仍存在细项缺口。准确的构建、测试、运行状态与剩余功能以 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) 为准。下方任务表作为验收追踪清单，不能据模块级描述判定全部完成。

已具备：

- Vue 3/Element Plus 完整管理界面、主题、登录/启动流程、响应式布局、真实概览、个人门户和权限裁剪。
- ASP.NET Core Cookie + OIDC Code/PKCE、动态组角色映射、两小时权限快照、CSRF/Origin 防护和管理权限复核。
- Domain/Application/Infrastructure/Api/Worker/Agent/Contracts/MaintenanceHost 分层及架构测试。
- PostgreSQL/Valkey 数据层、指标、任务、审计、门户、治理、应用、数据库、备份和 Docker 事件模型。
- systemd Host Agent、Unix Socket、短时能力票据、受控 helper、稳定维护入口和核心资源保护。
- 六类数据库/缓存适配器、备份、应用生命周期、容器与 Docker 管理、计划任务、告警、配置仓库和平台诊断。

当前发布物已切换至真实工作站。后续继续补齐功能细项、操作闭环和最终账号回归；`HOLD` 与明确设计预留项仍不进入当前任务池。

## 8. `HOLD`：不进入当前任务池

以下能力不创建开发任务、路由或可调用 API：容器终端、数据库恢复、文件管理、防火墙/网络写操作、外部告警渠道、GitLab 部署与同步。解除 `HOLD` 必须先更新产品基线、权限、RPC、数据模型和威胁分析。

## 9. 每个任务的完成定义

- 业务规则在 Application/Domain，Controller 只做传输，Infrastructure 只实现端口。
- Nullable、分析器、格式和架构测试通过。
- 有正常、拒绝、冲突、依赖失败、取消/回滚和权限下降测试。
- 涉及数据库时包含可回滚 EF migration 和迁移测试。
- 涉及 Agent 时包含 Unix Socket 授权、资源保护、幂等和重启恢复测试。
- 涉及前端时包含加载、空、错误、过期、无权限、暗色、响应式和减少动画状态。
- 日志为有界结构化 JSON；高频指标和成功轮询不写 Info 日志。
- 文档、API 契约、运行配置示例和安全说明同步更新。
- Secret 不进入 Git、日志、审计、截图快照或测试固定数据。

## 10. 发布验证命令

```powershell
dotnet restore
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build

Set-Location web
corepack pnpm install --frozen-lockfile
corepack pnpm lint
corepack pnpm test:unit
corepack pnpm build
```

每次 Agent 或宿主机 helper 发生兼容性变更后，仍必须在 Linux 工作站执行 systemd、Unix Socket、Docker 故障注入、Docker 重启和核心容器回滚的端到端验收；高风险的主机重启和系统更新只在明确维护窗口执行。
