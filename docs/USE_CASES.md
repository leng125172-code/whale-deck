# WhaleDeck 后端用例

2026-10-21范围覆盖：用例按[单工作站实用版59项](SCOPE_SINGLE_WORKSTATION.md)实施，不再为17个移出项注册接口或任务。单机管理、个人门户、显式授权开发空间及保留的网站/恢复/通知/GitLab等能力继续完整实现；不因取消企业租户而放宽身份、资源所有者、核心保护和失败恢复规则。下方旧范围记录仅作历史。

范围修订：2026-10-13 [P0–P5 基线](GOAL_P0_P5.md) 优先于旧 HOLD。以下是现有用例，不代表新增恢复/文件/网络/终端/网站/邮件/DNS/多节点业务已实现；新任务须补全 Application 用例、权限、计划/确认、失败/恢复、审计与原生验收，再注册 API。

本文定义应用层用例。HTTP Controller 只负责传输、模型绑定和状态码；授权、校验、幂等、任务编排和审计均进入 `WhaleDeck.Application`。

新增 `UC-DEV-001..010`：空间创建/环境变更、Git/上传导入、IDE 会话、构建测试/调试/取消、报告查询下载、启停/快照/删除。契约位于 [开发空间后端用例](DEVELOPMENT_WORKSPACES.md#5-后端用例与接口)。只允许代码调试测试，不合并生产部署接口；授权开发者使用资源级权限，不继承一般容器/宿主管理权。实施前此设计不代表 API 已注册。

## 1. 通用规则

### 历史目录捕获恢复（18f38bb/Agent1.33已签收不存在目标子范围）

管理员 `POST /api/v1/files/tree-restorings` 只提交 `captureId/target` 和唯一UUID幂等键。Application/Repository从签名捕获目录解析原资源owner、源位置/版本和清单，不接受浏览器提供这些事实；返回独立计划Job，完整扫描后五分钟签名计划等待确认。`GET /{id}`、`GET /by-key/{key}`只读恢复原意图；`POST /{id}/confirm`版本与原登录绑定，永久执行Job独立且确认重放不重做；cancel与acknowledge按原登录、版本、二次确认和Root回执栅栏执行。

确认时获取源/目标共享层级锁与捕获token锁，原路径相同先去重；只恢复到不存在目标，不覆盖，HDD捕获及私有原件保留。Worker复核管理员/期限/取消、续租并进行独立UDS能力调用；开始后未知仅观察或封存，不自动Apply。当前管理员第九类 `tree-restore` 可独立计划后对账/承认未知，不能冒充旧登录或伪造成功。Job/Outbox/人类审计/最终锁释放同事务，owner和私有计划不进入响应/审计。真实身份BFF/安装态与目录不存在目标的桌面/手机网页已签收，包括新管理员恢复已删除账号留下的捕获；第九类中断实盘接管与目录覆盖恢复/清理仍待签收。[后端原生验证](qa/FILE_TREE_RESTORING_BFF.md)、[页面证据与边界](qa/FILE_TREE_RESTORING_UI.md)。

### 文件文本预览和版本冻结保存（931a24c已签收子范围）

管理员 `GET /api/v1/files/text?rootId&path&expectedVersion`：登记根、普通非保护文件、最多1MiB，先完整流/版本/摘要/严格UTF-8校验与元数据审计，再NoStore返回正文、BOM、换行格式。无效UTF-8/NUL/过大400、旧版本409、普通用户403/匿名401；不返回局部成功正文，不进入日志或浏览器持久存储。保存没有绕过确认的新写接口：冻结打开时版本→原上传计划→二次确认→永久任务/Worker→1.25 HDD前置复制→原子发布，冲突保留本地可下载草稿。当前实际部署状态与失败/清理边界见[专项账本](qa/FILE_TEXT_HDD.md)，不能将文档视为实机验收。

- 查询用例返回 DTO，不把 EF 实体、Docker 原始对象或 Agent 消息直接暴露给前端。
- 管理用例仅允许 Authentik 管理员组；个人门户用例允许资源所有者操作。
- 管理员组缓存最长 2 小时。重新校验后权限下降，拒绝后续管理请求并取消该用户尚未开始的管理任务。
- 写操作必须接收幂等键；长任务返回 `202 Accepted` 和 `jobId`。
- 错误使用 Problem Details，至少包含稳定错误码、`traceId` 和可安全展示的说明。
- 写操作记录审计事件；敏感值、完整环境变量和数据库密码不得进入审计详情。
- 同一资源上的互斥操作使用资源锁，避免更新、删除、备份和重启并发执行。

### 容器资源查询与刷新

管理员 `GET /api/v1/containers/usage` 获取 Agent 的统一缓存批次，不触发原生采样。CPU 100% 为一个逻辑核心，内存扣除可回收文件缓存；网络/块 I/O 为累计字节。首次或计数器重置为 Warmup，停止和失败保持空值，超过 18 秒显示过期状态。未登录返回 401，普通用户返回 403。

容器页面默认每 6 秒刷新，支持关闭及 30/60 秒周期、手动刷新。后台刷新不覆盖整个面板，慢请求不重叠；标签页隐藏或离开页面停止轮询，权限丢失取消请求并清除管理数据。卡片与表格共用同一资源组件。

Worker 批量保存 `container.cpu.utilization`、`container.memory.used/limit/utilization`、`container.network.receive.total/send.total`、`container.block.read.total/write.total`、`container.pids.count`；历史窗口遵循既有指标策略。设备 ID 为 Docker 完整容器 ID，资源 ID 为登记资源 UUID。重复读取缓存按 PostgreSQL 微秒精度去重，不把 Warmup 的内部占位值作为实测零值展示。

### 容器创建流程

1. 服务端校验镜像来源、名称、端口、挂载路径、网络、资源限制和标签。
2. Agent 生成只读计划，返回冲突、将创建的资源和风险；不得在预检阶段修改 Docker。
3. 管理员确认后使用相同计划哈希提交创建任务，防止确认内容与执行内容不一致。
4. Agent 创建容器、等待健康检查并返回资源 ID；失败时删除仅由本任务创建的临时资源。
5. API 写入任务结果和审计，不记录敏感环境变量值。

### Docker 配置重启流程

1. `UC-DKR-002` 解析白名单字段，保留未知 `daemon.json` 字段，调用 Docker 原生校验能力。
2. 管理员二次确认影响和回退方案。
3. Agent 把任务写入宿主机操作日志，原子备份配置，发布维护状态，然后重启 Docker。
4. 宿主机稳定入口显示维护加载页；API/数据库不可用时仍可读取只读维护状态。
5. Agent 等待 Docker 与核心容器健康；超时则恢复旧配置并再次启动。
6. 平台恢复后同步最终任务与审计记录。
