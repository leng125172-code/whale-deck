# WhaleDeck 后端用例

本文定义应用层用例。HTTP Controller 只负责传输、模型绑定和状态码；授权、校验、幂等、任务编排和审计均进入 `WhaleDeck.Application`。

## 1. 通用规则

- 查询用例返回 DTO，不把 EF 实体、Docker 原始对象或 Agent 消息直接暴露给前端。
- 管理用例仅允许 Authentik 管理员组；个人门户用例允许资源所有者操作。
- 管理员组缓存最长 2 小时。重新校验后权限下降，拒绝后续管理请求并取消该用户尚未开始的管理任务。
- 写操作必须接收幂等键；长任务返回 `202 Accepted` 和 `jobId`。
- 错误使用 Problem Details，至少包含稳定错误码、`traceId` 和可安全展示的说明。
- 写操作记录审计事件；敏感值、完整环境变量和数据库密码不得进入审计详情。
- 同一资源上的互斥操作使用资源锁，避免更新、删除、备份和重启并发执行。

| 用例 ID | 用例 | 参与者 | 结果 |

| `UC-AUTH-002` | 完成登录 | Authentik 回调 | 建立 HttpOnly Cookie，不保存 Token 到浏览器 |
| `UC-AUTH-003` | 获取当前会话 | 已登录用户 | 返回 Subject、显示名、组、是否管理员、权限版本和到期时间 |

| `UC-AUTH-005` | 退出 | 已登录用户 | 清除本地 Cookie，并向 Authentik 发起登出 |

### 容器创建流程

1. 服务端校验镜像来源、名称、端口、挂载路径、网络、资源限制和标签。
2. Agent 生成只读计划，返回冲突、将创建的资源和风险；不得在预检阶段修改 Docker。
3. 管理员确认后使用相同计划哈希提交创建任务，防止确认内容与执行内容不一致。
4. Agent 创建容器、等待健康检查并返回资源 ID；失败时删除仅由本任务创建的临时资源。
5. API 写入任务结果和审计，不记录敏感环境变量值。

### Docker 配置重启流程

1. `UC-DKR-002` 解析白名单字段，保留未知 `daemon.json` 字段，调用 Docker 原生校验能力。
2. 管理员二次确认影响和回退方案。
3. Agent 把任务写入宿主机操作日志，原子备份配置，发布维护状态，然后重启 Docker。
4. 宿主机稳定入口显示维护加载页；API/数据库不可用时仍可读取只读维护状态。
5. Agent 等待 Docker 与核心容器健康；超时则恢复旧配置并再次启动。
6. 平台恢复后同步最终任务与审计记录。

## 10. 审计要求

至少记录以下动作：登录、退出、权限下降、权限拒绝、门户公共项变更、容器和应用写操作、Docker 设置、数据库/账号/权限变更、密码轮换、备份、计划任务、告警确认、系统更新、主机重启、自身更新和配置推送。

每条审计包含：`actorSubject`、来源 IP、动作码、目标类型/ID、结果、`jobId`、`traceId`、发生时间和脱敏详情。审计写入失败时，高风险写操作必须失败关闭；高频只读查询不产生逐次审计。
