# Runner 工件授权读取与原件退役

2026-11-09，代码 `7f549959`、`6d331c0a`。P3-17 增加 Agent 协议 1.67 的 `development.run.test-artifact.transfer`。内部 Gateway 按原运行请求、工作空间、运行回执摘要、工件摘要和字节数绑定读取及退役。两种调用使用独立的方法签名，重放和跨方法签名被拒绝。宿主只在该运行的私有目录内打开工件，重新核对内容、大小和文件身份。Agent 以 64 KiB 为分块上限，Gateway 收完后再次核对字节数和摘要。该通道的原件上限沿用 16 MiB。

退役先持久化绑定原运行及工件的凭据，再删原件。暂存中断时，同一请求可清掉遗留暂存并继续。凭据已发布时，读取立即关闭，重试退役可继续删除仍在的原件。重复退役返回同一绑定的回执，运行的原终态和清单继续可查。

- 使用标准自包含 Agent 发布包及最终宿主 helper，在断网 KVM 内经真实 Unix Socket 读取 Runner 实际生成的 **7,001,232 字节 JUnit** 和 **6,051 字节 TRX**，逐字节与宿主封存原件比对。Agent 重启后，原请求仍可读回同一报告。来宾日志未出现测试报告里的合成敏感标记。
- 使用另一已分配空间和错误摘要访问原件均被拒绝。同长度篡改后，读取和退役都拒绝，文件保持原样。还原后重复退役均成功，原件删除，原运行回执保持一致。
- 分别用两种中断夹具验证恢复。只有遗留暂存文件时，退役重试清理暂存并完成。退役凭据已经落盘但原件仍在时，读请求拒绝，退役重试删除原件。初轮来宾已经完成真实读取，测试客户端误把跨空间的绑定错误预期为 NotFound。修正预期后，以上场景全部通过。
