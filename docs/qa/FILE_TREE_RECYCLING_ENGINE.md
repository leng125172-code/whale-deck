# HDD目录回收引擎：内部源码，尚无公开入口

## 完整范围中的本批实现

独立的回收计划域、不可重做Root回执、私有隔离后缀和files-tree-trash授权。先核验完整目录manifest，再生成并完整验证固定HDD目录归档；只有HDD核验通过才开始移动原文件。按预先核对的相对名称逐文件校验/hash/NO_REPLACE移动，原文件inode保留在操作专属root/0700隔离树；最后只rmdir已核对且为空的目录。不会将祖先目录整体移走，不递归删除，不混用普通文件回收或目录移动的计划/回执。

隔离前及逐文件阶段重新解析当前父路径并核对inode，拒绝父路径替换。HDD捕获锁持有至源保留过程完成，归档/清单/存储策略在过程前后复核；根权限改变或取消/超时停止后续效果。Root命名空间和操作锁、清单/条目/字节/时间/回执预算延续现有有界约束，1GiB以上目录不借用普通单文件1GiB Inspect限制。副作用前写Root阶段事实，异常只观察；部分对象、坏归档/清单/未知替换文件不自动清理或重做。

原路径已消失且HDD和私有全部原文件/完整成员/哈希/inode均能独立证明时，恢复观察才可完成回执；否则Unknown保留现场。HDD校验前失败为Aborted且原件不改，开始源保留后无法证明的结果不伪装成取消成功。当前已经能与独立HDD恢复引擎组成“回收原目录→从归档还原原路径”，恢复产生新文件inode、旧inode仍保留；两份数据不互相覆盖。

恢复引擎额外只接受本轮两个新授权标签（restore/trash）的精确新增组合，以便旧捕获继续使用；路径、属主和其他策略仍须匹配，不修改旧备份/manifest或伪造原身份。

这不是完整P2验收。覆盖恢复、彻底删除/长期清理、可信安装/固定helper/Agent RPC、持久业务计划/任务/锁/当前权限复核/审计、目录历史列表与WebUI仍待实现和实际身份验收。当前运行时保持adc6cae/RPC1.31，默认根未升级，没有开放本批CLI/API。
