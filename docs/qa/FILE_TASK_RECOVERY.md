## 已实现的基础

- 管理员专用GET `/api/v1/files/recovery`、`/{kind}/{id}`，统一查询上传、普通变更、历史回收恢复、目录复制和目录移动五类持久Unknown元数据。原有按原登录查询/确认的接口不放宽。
- Application在读前和返回前均复核当前管理员；不构造旧用户的TerminalActor、不复制旧登录Cookie/Token。只读查询没有Agent/Root依赖，不改变原任务版本、状态、租约、路径锁或永久回执。
- 最大50项/页。先分别投影有界的小型排序键，再只加载选中一页的私有模型，避免读取五整页的大计划JSON。UTC时间、工作流类型、UUID稳定seek；游标严格规范化，不是授权凭据。清单是交互式当前状态，不承诺并发新增/终态变化时的不可变导出快照。
- 逐种复核既有请求/计划MAC。`Integrity=Verified`仅表示原绑定通过，不表示Root文件操作成功或当前文件完整；绑定异常明确返回InvalidBinding，不返回未经核实的源/目标路径与留存标记。不输出原LoginBinding、OwnerHash、RequestHash、PlanHash、PlanJson或完整Root清单。`RootStartRecorded`只是意图记录的开始标记；留存未知用null，不把未知写成false。
- 当前管理员确认采用独立MAC及登记/执行ID域，绑定当前Actor/Login、原类型/意图/执行ID/版本/绑定摘要、观察摘要/Root状态、处置类型、原因枚举与最多5分钟有效期。未知确认和有完整回执的成功对账严格区分，不能把未知伪装成Completed，不能携带Apply或任意命令。固定枚举原因避免自由文本中夹入Secret。
- 签名解析严格拒绝未知、重复或缺失JSON字段，即使MAC正确也拒绝歧义负载；复制/移动的既有Token不可作为管理员处置凭据。这个签名是未来确认门禁的一部分，不单独授予管理权或执行文件操作。
