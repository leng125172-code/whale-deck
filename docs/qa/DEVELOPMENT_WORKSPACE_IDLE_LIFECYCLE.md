# 闲置开发空间停用与恢复

2026-11-10，本批实现 P3-17 的一个子功能：所有者或当前管理员可以核对计划、显式确认停用闲置空间，并在重新核对原存储及权限后恢复。**当前仅通过候选验证，尚未完成新版本的 CI、标准部署及真实身份验收。** 实机仍为 `66a8598d`；不据此增加主任务完成数。

停用保留工作树、配额、预算、历史任务、报告及审计。它要求运行、导入和报告资源已经收尾；结果未知或仍有执行资源的空间拒绝停用。旧 Git 取消尚无明确的进程退出回执，因此同时使用保守的收尾等待和固定 cgroup 的实际空闲核对。运行中的任务仍应通过原取消流程处理。

数据库使用独立生命周期状态和单调版本，事务行锁串行化停用与新运行/导入；数据库触发器也拦截旧生产者在非 Active 状态插入新意图。Worker 在执行前后核对当前身份，使用独立签名能力及固定 root helper，只有收到绑定原分配证明、操作 ID、计划摘要及版本的宿主回执才完成。丢失响应继续原操作；原执行者失效时，当前有权操作者可重新授权，原任务发起人保持不变。普通跨用户请求不可接管空间。

宿主在共享运行/源码锁排空后持独占锁，重新核对真实文件系统、inode 和强制项目配额，原子发布持久标记。停用标记阻止新的 Runner、源码暂存、发布及重复分配；读取、状态查询及收尾仍保留。同一操作可以重放，旧版本或不同操作不能覆盖新状态。恢复仍占用原预算，不新建分配。生命周期历史存在时拒绝撤销该数据库迁移，防止历史状态丢失。
