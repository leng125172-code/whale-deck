2026-10-14，P0-07 / P2-12 / P4-06 的增量，不是完整外部通知完成。当前实现配置 CRUD、投递列表及管理员 UI，尚未实现目标私有值配置/解析、传输适配器、发送 Worker、签名/发送限流/测试发送、逐次尝试历史与批准目标真实投递。页面明确提示“不表示消息已发出”，不会制造投递记录。

## 接口与权限

REST 根路径 `/api/v1/notifications/manage`；管理员才可 GET/POST `channels`、GET/POST `routes`、PUT/DELETE `channels/{id}` 和 `routes/{id}`、GET `deliveries`。Controller 只做 HTTP 映射；服务层再次检查服务端目录解析的主体/管理员身份。所有列表 NoStore、按创建时间/ID 稳定排序，page 从1开始，take 限1–100，路由/投递支持 channelId，投递支持固定状态过滤。

写请求必须 Cookie 防伪与合法 Origin、UUID `Idempotency-Key`、`confirmed=true`。更新/删除必须 expectedVersion；并发版本冲突409。创建不接受 expectedVersion。只保存严格64字符引用标识 `\A[a-z][a-z0-9-]{0,63}\z`，不是 URL、邮箱或密钥；不接受路径或命令。类型 Email/Webhook/DingTalk/WeCom/Feishu；来源 all/Alert/Job、级别 Info/Warning/Error/Critical。新渠道默认停用。

渠道 DTO 只返回凭据是否存在，不返回 credentialReference 或值；投递 DTO 不含租约 token、任何私有引用/渲染消息。保留凭据只能在更新且未指定替换引用时使用；改变 provider 必须明确替换/移除，不能偷偷沿用其他类型凭据。

## 事务与重试

- 配置变更和固定目标审计同一 PostgreSQL 事务；审计只存请求哈希，不存引用正文、真实目标、密钥或请求体。没有网络发送。
- 全局短时事务 advisory lock 序列化预算检查与写入；最多32个启用渠道、512条启用路由。lock_timeout3秒、statement_timeout10秒，超时失败；不用事务中网络重试。
- 主体/请求键生成稳定资源 ID 和审计回执，规范请求哈希验证重放。提交响应丢失后重试不会再次创建/更新/删除，也不重复审计；相同键不同操作或载荷409。数据库执行重试无 EF 追踪新增对象残留。
- 新 HTTP 重放返回资源当前元数据，不承诺历史逐字段响应；原资源之后删除则404，不重新创建。删除重放204。幂等回执与审计保留周期一致，不承诺永久跨保留期重放。
- 所有渠道更新、路由新增/更新/删除都会提升父渠道版本；确认文案明确尚未发送的旧意图取消，Sending 不撤回、不自动重发。重叠路由允许，派送按事件/渠道去重。
- 有投递历史的渠道不能删除，改为停用。无历史渠道删除会级联移除其路由，不删除其他渠道。
