## 实现

`validate_container_recycle_archive_copies.py` 在全新自有资源完成回收、Originals 清理和归档复制后，仍按显式30天留存预留 A；随后调用真实 `ContainerRecycleArchiveRetirements.apply()`。不传调用方时间、不改原 createdAt、不修改系统时钟、不降低留存下限。只有精确 `CONTAINER_RECYCLE_ARCHIVE_RETIREMENT_NOT_ELIGIBLE` 可接受；成功返回、其他拒绝理由、异常或任一前后状态变化均失败并保留未签夹具。

新采集器保存自然墙钟边界、单调耗时、实际读取的 Reserved Root/marker、完整退役注册表，以及 archive/source/purge/restore claim/HDD/容器命名空间前后快照。仅已有 Reserved 的 Apply 被允许调用，拒绝不得生成版本2执行态、修改 marker、删除负载或维护日志。

`archive_retirement_preexpiry_proof.py` 是纯验证模块，不导入宿主执行器、不读写文件、不调用恢复或删除：

- 严格检查自然墙钟均在 capture 与 due 之间、retainDays1–3650、无布尔/浮点时间，单调耗时0–120秒。
- 验证年轻且副本有效的计划、独立域指纹、四个不同操作ID、固定 owner/request、准确拒绝原因。
- 规范 JSON 语义绑定预期 Reserved 日志和 marker，同时用实际读取 JSON 的序列化顺序重算原字节长度/摘要，与 Root 物理快照 join；单链接、root:root/0600、已有空锁一并核对。
- 前后四组事实逐字节等价；原 Completed 复制日志、claim 域摘要、原链/存储/归档身份、HDD完整数据快照和实际副本新 inode/属性/摘要互相绑定。
- 独立 live 和 final 验证器必须读取该证明，并将它 join 到预留步骤 A 的真实注册表快照和共同保护基线。不能只靠“NOT_ELIGIBLE”文案或一个通过布尔值。

这是有时间边界的前后观察，不是对不可见中间系统调用的原子追踪；也不授予未来删除权或证明容器可写副本永久存活。真正到期执行仍须重新授权、围栏、验证和独立签收。
