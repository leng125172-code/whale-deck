## 互斥与恢复边界

内部锁顺序为清理预留journal → 原来源journal → HDD gate；独立恢复是恢复journal → 同一来源journal → HDD gate。来源锁内重核完整预检计划后，先保存 `Preparing`，再fsync来源 `<sourceId>.purge.json` 的 `Reserved` 围栏，最后保存独立 `Reserved` 回执。来源围栏绑定完整来源引用、新operationId、owner和计划指纹；清理预留journal使用独立0700目录，不混用来源或独立恢复目录。

旧原生恢复在既有恢复claim检查及最后命名空间交换前检查围栏；独立恢复的来源计划和恢复claim写入同样拒绝活动围栏。正常产品调用在同一来源锁内检查/写入；内部 `write_claim` 仍要求调用方持有来源锁，不能把单独一次检查当作外部并发授权。围栏的读取严格检查路径、schema、完整来源、root:root/0600、普通文件、单硬链接、大小及唯一JSON键，损坏、符号链接或不安全权限均拒绝。

明确取消只对已提交 `Reserved` 生效，先在来源锁内重新验证原件/HDD和完整计划，再持久保存 `Aborted`，最后将来源围栏改为 `Released`；保留释放标记，不删除它。同一ID迟到reserve只观察Aborted；丢失其journal时也不能借Released标记重新预留。不同新ID可在取消后重新预检；旧ID的迟到取消不能释放新ID的活动围栏。

Preparing之前/之后、来源围栏已保存而独立回执未提交、回执已提交、Aborted已保存而尚未释放，以及释放完成分别有明确边界。半写入、孤立来源标记或已提交预留丢失来源标记时保存 `Unknown`；在不覆盖其他活动ID的前提下重建Unknown保护，不自动重做工作。Unknown的discard不会释放围栏；相关明确人工处置业务尚待实现。若取消重核发现HDD/原件改变，拒绝取消并保留Reserved保护。本批没有任何删除阶段，`purgeApplied=false` 仅说明这一候选从未实施purge，不能作为未来删除实现的通用推断。

未来实际删除必须增加独立、持久的删除阶段和清理完成标记，在受保护临界区再次核验，配合权限、明确确认、租约、任务、审计及不可逆写入故障处理。启用前必须同时部署所有恢复入口的新版围栏检查，补齐版本/能力拒绝和安装验收；旧安装态恢复程序不认识本候选，不能将候选围栏写进生产后便认为已获得互斥保护。
