## 传输、权限和失败处理

新增POST `/api/v1/containers/{containerId}/files/acls/restores`及GET `/{id}`、`/by-key/{key}`；返回`{intent,source}`，来源为完整只读元数据快照，意图仍是原ACL永久意图。响应NoStore，登记202的Location指向恢复状态。Controller只做身份/传输，现有BFF Cookie、CSRF/Origin和Administrator策略继续有效；业务的实时管理员与原登录授权仍在来源前后、入库前后和状态返回前校验。

登记body严格只接受instanceId、path、captureId、expectedHistoryDigest、expectedVersion五个显式字符串；重复/缺失/大小写别名/额外字段/null或错误类型拒绝，不接受调用方ACL条目、属主或原计划。必须一个非零规范UUID幂等key。读取原key/ID只返回同一原登录意图，跨容器或其他登录不能读取；状态读取不依赖历史在线，也不会自动登记或更新期限。确认和取消复用原`/acls/{id}/confirm`与`/cancel`，原ID作幂等key，仍由后台规划/执行，HTTP请求不直接修改ACL。

来源读取缺失/变化→409，Unavailable/Unimplemented→503，PermissionDenied→403；坏来源或撤权不返回私密ACL、不登记新意图。客户端中止向来源读取传播，未完成读取不入库。现有普通ACL与新的恢复任务不能用同key互换。没有新migration/数据库实体/Agent protobuf、minor或权限；此前来源列迁移仍未应用生产。

## Vue实际行为

当前管理员在准确对象的ACL历史中读取所选快照后，点击“从此历史生成恢复预检”，进入复用的ACL任务弹窗。来源捕获ID/摘要/原实例/留存时间和完整目标条目只在内存展示，清楚说明仅恢复历史对应access或default一类、不递归、另一类ACL/属主/内容/现有子项保持；default空列表是明确清空。来源只决定所选目标类型和条目，浏览器提交的登记body没有ACL正文。

新预检后逐条展示当前access/default ACL、UID/GID、执行身份、目标ACL与目标普通模式、期限和后端确认警告；必须显式“确认ACL历史恢复”。仍保留写前当前ACL原件的后端规则，但本批测试回执不能作为实际HDD备份发生的证明。状态、原Root回执与历史不确定性沿用原ACL解释；Unknown保留共享保护并引导异常处置，不自动重试写入。

完整来源/位置/类型/条目/模式与原命令、当前版本均严格校验；后续响应不得替换已选来源或降低版本。来源在Vue响应式对象外深复制，避免DataCloneError或后续数组变更污染原请求。登记POST即使幂等重放返回执行状态，也必须先查询原key，不能据登记响应冒称新确认成功。

浏览器只保存原key/ID、Subject/CID及`restore:true`模式提示，不存ACL、capture/digest或OIDC token；兼容旧普通ACL四字段提示。登记丢响应后刷新只GET原引用；无明确原响应不自动换key。确认丢响应时按钮禁用，查询原任务对账；原计划过期、实例变化或来源响应不一致时不允许确认。取消有独立二次确认，关闭不是取消；作用于原新执行，不回滚已完成变更。锁和原有ACL任务共用，同路径其他写入继续禁用。

generation/AbortController/原状态单调校验丢弃迟到响应；会话结束/撤权清空提示和私密源，关闭尚未登记草稿清空源。隐藏页暂停原任务轮询，恢复后只查询；历史面板关闭/换目标/隐藏也清空。320×600明暗主题使用正文滚动及可换行固定页脚，确认和请求取消按钮在视口内；真实页面验收仍待。
