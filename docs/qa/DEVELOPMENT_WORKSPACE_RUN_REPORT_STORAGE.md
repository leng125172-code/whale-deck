报告仓储核对已结算原任务的工作空间、执行主体、运行 ID、时间和终态，以及入队时固定的跟踪 ID、源码指纹、环境和保留期。首次写入在同一事务中检查原任务，保存 Markdown、JSON 和两份摘要。重复提交相同字节返回原结果，不同内容冲突。两个格式各限 512 KiB。数据库校验正文摘要，拒绝原报告改写。读回时再核对范围、保留期和所选格式摘要。

到期清理按批释放正文并保留身份、摘要和到期事实。读取在到期时即拒绝，即使清理尚未运行。保留历史时降级会报错，避免迁移删除已有报告。

## 实际验证

- 真实隔离 PostgreSQL 验证原任务缺失或运行中拒绝写入，错误工作空间、运行、身份、跟踪、源码、环境、保留期和终态也被拒绝。两个独立连接并发提交同一报告只创建一份，读回两种格式的字节与 SHA256 一致。不同内容冲突，数据库也直接拒绝改写。
- 首次成功后复核发现 .NET 时间刻度比 PostgreSQL 更细。将报告统一到微秒，再从真实数据库读回开始与结算时间重建报告，仍识别为已保存。验证按批清除过期正文、保留摘要、阻止过期重放及非空降级。
- 首轮原生用例在 EF 生成迁移的 IDE0161 和 CA1861 检查处停止。修正生成代码后两次真实数据库专项通过，最终一轮 108 个阶段标记，耗时约 2 分 27 秒。临时数据库容器与网络已清理。Release 6,197 项单元、822 项默认集成通过，默认集成有 7 项按原生依赖条件跳过。EF 模型无待迁移变更，8 项范围检查和 14 项前端 CI 合同通过。
