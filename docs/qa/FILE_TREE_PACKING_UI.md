## 用户可见功能与验收清单

- 目录行新增压缩入口，要求管理员及独立的源 `files-list/download/archive/tree-pack` 权限；目标要求 `files-upload/mutate/archive/tree-pack`。没有合格目标时说明原因并禁用生成计划，不自动扩权。
- TAR/GZ 双格式与扩展名联动；TAR仅打包、TAR.GZ压缩。保留Linux名称原大小写和中文，按UTF-8字节检查路径、拒绝穿越、目标与源重叠及格式不符。
- 扫描和执行为两个阶段；显示源/目标、格式、完整扫描计数/大小、独立任务和明确确认。关闭弹窗只是收起，关闭引用不取消原任务；取消和Unknown处置均需独立确认。
- URL只保存不透明登记键/任务ID，不保存计划签名或凭据。刷新按原ID/键GET恢复；丢登记响应不重复POST，丢确认响应先查询原任务。目标/格式/摘要响应异常时保留引用，禁用陈旧确认及下载。
- Succeeded才显示归档大小/完整SHA与回执绑定的专用下载链接；服务端确定附件名称。浏览器原生流下载，不使用页面Blob，不依赖HTTP环境不可用的安全上下文文件API；浏览器显示真实进度和失败，不在点击后伪报成功。
- 身份失效/权限拒绝清除元数据和轮询；普通用户初次/刷新深链不请求文件工作流。多个原引用不叠加初始压缩/复制弹窗，不产生新任务。
- 功能与视觉分开检查：320/1045/1440明暗Ready/Completed，小屏密集Unknown、长路径和完整摘要；独立探索收起重开、确认框取消、Unknown明确接受及格式往返。

## 保留的失败与修正

- 首次类型检查发现编译目标不支持数组 `.at`，已改为兼容方式，最终下载名称交给现有安全附件响应头。
- 首轮21个浏览器用例20通过/1失败：点击Element Plus内部输入被可见已选文本阻挡，改为正常点击可见文本；未强制点击或放宽等待/断言。
- 随后的下载夹具发现Chromium带HTML `download`属性的请求发生拦截外重发，因没有真实API而失败。确认后端本有安全attachment响应头后删除重复的前端属性；浏览器导航到同一专用下载入口，失败在独立页而非覆盖工作台。夹具使用实际回环HTTP响应证明保存完整字节，再通过原生下载断言；真实生产下载仍待网页签收。
- GLM `glm-5.3-flash` 只读首轮定位1次超时，180663ms；没有可用结论，Tokens/费用均未返回，不估算。GPT接手实现、复核和测试，没有借第三方处理凭据/权限操作。
