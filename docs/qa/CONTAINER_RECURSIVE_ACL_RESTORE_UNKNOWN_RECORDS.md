# 目标重命名后的Unknown原件与计数展示候选

2026-11-05，承接[标准Partial退出](CONTAINER_RECURSIVE_ACL_RESTORE_PARTIAL_LOGOUT_GATE.md)。本批新增恢复域专属Unknown原件证明，并直接修正Vue任务摘要对Unknown聚合计数的表述。尚未发布，也没有真实工作站Unknown/管理员处置整链证据，不扩大旧签收范围。

## 实际行为与精确证明范围

临时Linux文件系统真实恢复首项后，在AfterEntry检查点将原树根级`one.bin`重命名为`renamed.bin`。引擎检测树变化并拒绝，inspect返回Unknown，四计数零/unknownCount=4；但首项原Completed子记录及实际ACL改变仍保留。新证明严格绑定此固定文件对、完整来源/本次清单/HDD前像、首项Applying时完整物理快照及子记录，不能把聚合0解释为没有发生修改，也不能套用Partial1/1/0/3/0。

Unknown读取入口仅允许finishedThrough=0、startedThrough为0或1，实际JSON子记录只有已完成首项，第二个started标记本身不是第二个子回执。多余子Root/HDD记录、其他游标/Unknown形态均不签。原Partial/Applying入口仍严格0/0，没有放宽。Unknown五计数必须0/0/0/0/n且outcomeDigest为空，Root与回执/HDD一致；cut与Unknown的聚合HDD、首子Root/HDD另作原始字节比较。第一项真实改变独立证明为1，返回knownActualChanges，不改写聚合计数。

重命名证明要求原路径确实缺席、新路径保持原inode/device、mode/UID/GID/link/size/mtime及ACL/属性，目录root身份和ACL保持，仅允许其时间戳/目录大小随重命名变化，其余对象精确不变。只读检查不恢复旧路径。迟到Apply和再次inspect在禁用ACL写入器下仍返回Unknown、检查点不重复，实际树不再改变。这是临时目录、容器/存储配置见证为显式夹具；不是生产HDD、真实Docker命名空间、签名RPC、生产SQL或身份/UI链路。

## 产品UI修正

Unknown或原回执仍Unknown（包括处置后）时，原“实际修改”标签改为“回执已证明修改”，显式说明0不代表未发生修改、没有回执时保持未证明，并将历史提示中的“本次实际修改数”改为“本次回执计数”。正常成功、Partial与无歧义回执沿用原标签，原26字段JSON/业务计数不改写，不把原件证明的1塞进API聚合0。无回执的五计数继续显示未证明。观察工具同步要求新标签和说明，部署新版后才能据新工具签Unknown页面。

## 测试、失败与候选边界

新增9个实际临时ACL/重命名/原件测试及1个Unknown说明负向检查，关联147项root工具通过、零跳过。覆盖首项真实改变/全树差异、迟到不续做、Root/HDD/子记录替换、将Unknown误标Partial/零未知、额外子JSON、固定场景与路径越界、相同JSON但字节改变。首次新增字节比较有2失败：归档副本在默认umask022下为0644，被严格私有读取先拒绝；归档函数改为O_EXCL/O_NOFOLLOW显式0600创建，旧副本必须0600，不放宽比较。新增宽松umask与非私有旧副本拒绝测试，复验通过。原证据不改写权限以掩盖失败。

前端1292单元通过，包含32项摘要专项；类型、生产构建、Oxlint/ESLint和格式检查通过。最初条件式expect触发4处lint错误，改为无条件数据断言后通过。两次辅助脚本在web工作目录使用错误相对路径而未修改目标文件，修正后继续，未影响产品构建。生产构建预览先4场景通过，随后将无回执说明和历史文案进一步明确，重建后最终4场景（320/1440×明暗）再次通过；最终56图包括12张不确定性说明图，所有API/身份/SSE为显式夹具，不能算工作站真实登录、恢复或处置。旧中间预览记录保留，不与最终4场景累加当覆盖。

新Root级重命名证明不支持容器整体消失、第二子实际启动或记录出现、其他名字/路径、磁盘失联等情况；4对象测试不签26对象实机。下一步冻结/CI后标准覆盖前端，再接精确自有目标变更、真实Unknown/原件/Job/API/不同管理员处置及前后独立清理。原维护失败、源/HDD同device限制与其他59项保留，不提升整项或阶段完成率。
