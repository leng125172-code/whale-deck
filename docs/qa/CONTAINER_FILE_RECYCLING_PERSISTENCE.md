## 持久化与保护

`container_recycle_intents` 保存原请求、计划、独立执行 job、MAC、租约、开始标记、发布保护、回执/投影与明确处置记录。规划/执行分别外键关联 Job，均 Restrict；唯一幂等键、执行 job、租约和活动发布保护受索引约束。18 项 CHECK 校验状态/期限/来源身份、普通单链接文件、属性、完整回执及 Unknown 的可空源事实。

SQL 形状校验保留 uint64/有符号纳秒边界、严格实例 PID/日期、相对路径与段长度；属性只接受 `user.*`，按 UTF8 字节排序，Base64 规范编码、32 项与4096字节总量受限。业务 MAC 仍由服务端验证，SQL CHECK 不冒充 MAC 验证。未知源事实必须为 null，不能用 false 填补。

所有转换使用既有事务门 `41307341`，登记/确认与 Job、Outbox、事件和审计一并提交。带令牌和期限的租约控制落终态；开始标记不可擦除，重领只能观察原执行。请求、已有计划、执行身份、开始标记、已知回执事实和终态不可改写，永久意图不可直接删除；Unknown 只允许继续保留或明确处置，不能改成成功。非空表禁止降级。

新增 13 个触发器覆盖本表、11 个既有容器写入表和宿主路径锁，双向持有相同事务门。各现有 C# 仓储也增加回收保护检查、同容器父子路径保留与全局/主体预算；不同容器可能挂载同一宿主路径，实际发布保护采用已有保守的全局互斥策略。没有改写旧迁移。

专用 Worker 已在候选代码接线，通用 Outbox 分派明确排除回收消息，通用 Job 重试拒绝重新执行回收。Worker 的周期日志保持有界；本批没有启动生产中的新 Worker。任务详情专属结果摘要与新页面仍未接入，现有 Job 状态不代表完整 UI 验收。
