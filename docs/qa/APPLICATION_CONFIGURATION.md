## 完整编辑与备份仍需验收

本轮完整编辑链与前端表单正在实现，以下检查完成前不标记上线。新增控件与证据清单：

- 读取、重读、关闭：脱敏字段/已知名称、读取失败、403 清除、关闭后迟到响应，截图检查 loading/error/有数据状态。
- 服务页签：镜像、CPU/内存、重启模式、网络模式/批准网络、端口、Cmd/Entrypoint 保留/替换/默认；逐项修改并还原，验证仅修改字段进入候选。
- 数据挂载：添加/移除/类型/来源/目标/只读；固定 data 来源不可编辑，应用卷前缀约束，移除不删除数据。
- 环境覆盖：名称、新值（空值/换行）、移除输入、移除已有覆盖；真实值不回显，重复/冲突名称拒绝。
- 更新策略：自动更新完整开关、版本范围、窗口和已安装依赖；错误输入预检拒绝，不写配置。
- 提交方式：仅保存/保存并重部署、预检、确认/取消、任务中心结果；只有二次确认后入队，取消不执行。
- 分别检查 1440/1920、1045、390/320 明暗主题初始页签、展开挂载/环境/命令后的稠密状态、页尾提交区与确认弹窗，不以页面 scrollWidth 代替局部控件可见性。
- 探索：预检冲突后重读再确认、关闭时迟到响应、403 时清除输入、切服务/切模式/取消再重开。原生验收对照 Docker Env/资源/网络/挂载，证明保存未重启与重部署健康，且未改动核心数据。

- 应用参数：镜像、CPU/内存、重启策略、端口、命令/Entrypoint、批准网络、应用拥有的卷/固定 data 目录挂载、环境覆盖、自动更新/版本/窗口/依赖。
- 未修改字段保留；原文件/未知扩展不被表单重建丢弃。密码/环境值/命令中的敏感值不回显，不进 PostgreSQL、任务/审计/日志；候选输入通过所有者绑定的短时票据，预检不消费，执行消费一次。
- 计划同时绑定原配置、服务成员与候选输入；失效/变更/重复提交拒绝；保存与保存后重部署明确区分。dev 不自动回退，失败可修复覆盖。
- 核心/未注册项目不可编辑；禁止任意路径、Docker/Agent socket、跨应用卷、受保护网络、特权/设备/宿主命名空间。默认 no-new-privileges/cap_drop 与有界日志保持。
- 真正安装一个隔离的临时应用，用 API → Worker → Agent 修改并对照原生 Config.Env、CPU/内存、端口、卷/网络与未知字段；验证配置指纹冲突、票据过期/所有者、一次消费、401/403、Secret 不泄漏。
- 环境字面值专门验证 $、单/双引号、尾反斜杠、换行、Tab、Unicode/空值。`compose config` 的输出会为再次执行而转义 $，不能将其序列化字符串当作容器实际环境值；原生容器 Config.Env 才是语义证据。
- 备份必须从真实批准适配器运行，显示范围/一致性/任务/校验与记录；禁止把配置快照冒充完整数据备份，不实现恢复。
- 前端 QA：所有按钮/模式/提交/二次确认/任务跳转/取消；1440/1920、1045、390/320 和明暗主题；单独截图与边界测量；迟到响应、权限失效、配置冲突、空/错误状态，短探索 30–90 秒。
