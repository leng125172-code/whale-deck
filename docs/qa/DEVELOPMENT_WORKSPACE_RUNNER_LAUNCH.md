# Runner 宿主启动与运行回执

2026-11-09，代码 `0b4f0ead`。标准宿主安装包含 root 专用启动器。入口重新验证已发布 NVMe 工作目录和硬项目配额，从登记环境的原始 JSON 摘要选择指定运行时。启动器只从固定 root 私有 OCI 缓存打开该摘要，复核现有 `work` 目录的 UID/GID 与项目 ID，再接上隔离解包和只读 runc 配置。镜像暂存、rootfs 与工作文件共同计入该空间的硬磁盘配额。

运行前写入绑定工作空间、运行 ID、环境、命令与预算的请求摘要。同一空间串行执行，状态查询在锁被持有时返回忙碌。完成后先确认 runc 状态清空、解除私有投影并删除 bundle，再持久化终态。重复请求和只读查询返回原回执，摘要变更拒绝。请求记录存在但没有终态时，返回中断并拒绝自动重跑。超时仅清理由空间 ID 与运行 ID 共同确定的 runc 容器。

## 实际验证

- 离线 Linux amd64 KVM 来宾从固定摘要的 Node 与 .NET SDK 镜像运行。Node 验证 UID 10001 并写入标记，.NET 实际编译和执行 C#。应用及解包都经 runc 1.5.2 的默认 pivot 路径。工作目录位于真实来宾 PCIe NVMe ext4 项目配额上。
- 实际拒绝环境字节变更和未登记的运行时，复用 ID 但更改预算也拒绝。同一请求启动、重试和观察返回相同回执，Node 的追加标记只出现一次。任务运行期间查询和启动均返回忙碌。真正超时后 runc 状态、cgroup 与 bundle 清空。启动凭据写入后以 SIGKILL 中断，启动和观察都返回中断。
- 初测发现宿主 root 复制镜像时可用 `CAP_SYS_RESOURCE` 绕过硬限额。启动器现于接触工作盘前移除该能力，并防止其在 exec 后恢复。来宾复验覆盖空间不足发生在镜像复制和解包两个位置，失败后删除暂存并重新验证空间配额。解包器内部的配额拒绝返回解包失败。 [Linux 配额硬限制实现](https://linux.googlesource.com/linux/kernel/git/torvalds/linux/%2B/869b6ea1609f655a43251bf41757aa44e5350a8f/fs/quota/dquot.c)
- 5 项 Runner、2 项隔离、7 项 rootfs、5 项解包、23 项存储、8 项范围与 14 项 CI 合同测试通过。安装脚本通过语法检查。
