## 交付与检查清单

- 四种操作：新建一个叶目录、普通单链接文件复制/移动、普通权限位。API计划绑定源版本/完整元数据和SHA/父目录身份/目标不存在；确认后202持久意图、Job、Outbox、人类审计，Worker再核权/执行。
- 上传和新操作共用逻辑源/目标路径锁及宿主namespace提交锁；迁移接管已有上传（含Unknown）。已知默认登记根相互独立；自定义重叠根的别名/整棵子树锁不宣称完成。
- 取消：先记请求，固定root Discard落永久owner/plan绑定tombstone，再确认Canceled。结果未知保留路径锁与回执，不自动重做；人工核实后通过有版本约束的显式确认接受未知，不伪报成功。
- 登记响应丢失：冻结原计划/幂等键，仅重试原登记。resolve不创建任务，仅在计划过期且同一事务门证明没有迟到登记时允许释放未登记请求。
- HTTP权限：当前Cookie登录绑定、管理员、CSRF/Origin、精确幂等Header；普通/匿名及其他登录不能通过ID猜测查询。Swagger列出明确非递归/不覆盖/不改owner边界。
- 页面控件：新建目录、行更多→复制/移动/权限、根/目标路径/模式表单、计划/返回修改/取消/最终确认、任务状态/原任务链接/查询/取消、冻结重试/核实登记、未知二次确认。
- 可视检查：320/1045/1440宽度的明暗主题；长文件名省略且可完整提示，计划路径有界换行；固定行操作不截半截、表格内部横滚，页面不横向溢出。检查初始、计划、执行后/未知/错误态；人工查看截图，数值不替代目测。
- 探索/失败：取消计划无任务；坏路径/SUID模式拒绝；计划冲突；登记响应丢失；取消不将202当终态；Unknown不重发；撤权清理元数据；SQL审计失败整事务回退；租约丢失后只核回执不重写。
