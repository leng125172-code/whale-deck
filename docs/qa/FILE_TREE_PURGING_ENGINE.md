## 已实现范围与不变量

- `whaledeck-tree-purging.py` 以只读计划冻结一个捕获及明确的Archive、Originals或All范围；捕获必须有相符的Completed原始回收/覆盖操作，不接受任意私有路径。尚不清理来源未定的Unknown/孤儿捕获，这仍是后续管理恢复/长期清理工作，不因本引擎而删去。
- 来源绑定捕获ID/原owner/原路径版本/清单/类型，当前执行owner另行绑定；源根必须显式具备`files-tree-purge`及既有读取/变更/历史/归档权限。仅解析器认识新grant；默认登记根没有自动扩权。本批不向用户提供执行入口。
- 计划绑定当前policy、HDD配置/目录inode、捕获元数据、原root回执、清单与归档SHA/内容域、私有命名空间和保留树完整身份摘要。新增清理grant可精确兼容旧捕获，不放宽根路径、owner、HDD或其他策略变化。
- Archive只删除所选`.tar.gz`载荷，不要求旧父目录仍存在。Originals只删除来自相应原任务的精确私有树；All先处理原件，再处理HDD归档，使每个原文件unlink期间HDD归档仍保留。尚为Verified的HDD副本在Originals计划/执行前也会重新全量校验；先前明确清空归档后才允许另立计划清空最后原件，后续界面必须明确提示不可恢复/可能最后副本。
- 私有树与归档分别先改名到本清理操作专属隔离名，使用no-replace交换；逐个核对单链接文件、完整字节、父链/挂载与登记路径后unlink，目录只用rmdir。没有递归shell删除或任意执行命令。敏感名字、符号/硬链接、额外对象、挂载和身份变化拒绝。
- namespace/capture锁共用原子提交边界；每次删除前重新核对命名空间、根授权与HDD所选目录，不能只信一个脱离当前路径的已打开FD。完成前重读墓碑与路径，后来重建的新对象不再删除、也不报Completed。
- 原件/归档的清除标记分别保存，原始操作回执、捕获`.json`/`.manifest.json`/锁、SQL任务/审计不能由此入口删除。墓碑阻止旧操作重建被清归档，明确清空的载荷释放live-version名额；畸形/矛盾墓碑不释放。永久元数据另有100,000目录项硬预算，自动压缩/清理元数据仍未实现。
