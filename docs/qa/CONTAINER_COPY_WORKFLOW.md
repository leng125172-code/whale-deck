## 业务行为与安全绑定

- HTTP 只登记预检请求，不执行完整内容扫描或复制。后台规划完成后进入 Ready，返回五分钟有效的确认；
  确认创建独立执行 ID，与预检 ID 分离。取消确认不会复制数据。
- 原始请求绑定 id/key、原用户/原登录/trace、owner、精确容器实例、两条路径、原版本和固定十五分钟规划期限。
  独立计划 MAC 覆盖整个请求、全部文件/目录计划及 Ready 期限；独立执行 MAC 覆盖计划 MAC、执行 ID、确认时间及固定十五分钟执行期限。
  owner、请求 ID、执行 ID 和三种 MAC 使用独立域。进程重启不延长原期限。
- 同 key 重试原请求返回原意图；同 key 改命令拒绝。读操作不重新规划、续期或创建执行。
  普通用户、失效登录、错误容器/登录、未确认和过期确认不能产生新写入。
- 计划/执行 ID、inode/device 的 UInt64、纳秒 Int64、源/目标父身份、内层计划和当前目标证明全部保留。
  存储材料使用有界规范 JSON；未知或重复字段、非规范编码不能改变被签名含义。
- Dispatcher 对长扫描/复制每六秒复核原登录、当前管理员权限、取消、期限与租约，
  最后一次 await 后再次检查。申请发布保护后也复核，拒绝撤权与发送之间的旧授权窗口。
- 执行前先 Inspect 原 ID。只要 Root 开始标记已落下，缺失回执也不能再次 Apply；只能观察或 Discard 原 ID。
  丢回复、非法回执或期限耗尽不伪造成功。Completed 但目标已变化记 Superseded；历史成功不会被迟到撤权抹掉。
- Unknown 保留保护。另一个当前管理员只能通过明确二次确认和原 Root Discard 永久栅栏接管，
  使用原 actor/owner/执行 ID，不重签一个新执行，也不删除可能存在的私有对象或冒称它们已清理。
- Authentik/登录缓存不可用时，管理写入延后且失败关闭；不能把服务故障当作用户主动取消。
