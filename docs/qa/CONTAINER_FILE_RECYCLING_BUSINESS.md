# 容器普通文件回收：内部业务编排候选

2026-11-05，承接[安装态签名 RPC 与原件验收](CONTAINER_FILE_RECYCLING_AGENT.md)。代码冻结 `6607b73ba14d9e40d9db33092036b56fad7636d0`；本批实现回收意图、业务授权/确认、任务分派与 Unknown 处置规则，并用内存仓储和模拟身份/RPC 验证。尚未实现实际 PG 仓储、生产 Worker/API/Vue 或恢复业务意图，不能把本批单元测试当作永久业务整链验收。

## 已实现的候选规则

- 回收独立 Domain 意图及 Application 仓储契约，保留原登录、Subject、trace、幂等键、容器实例/路径、原命令和期限。规划与执行 job 不同；请求、计划、执行、确认、回执分别使用独立业务 MAC 域，不复用 chmod/所有者权限。
- 首次登记只校验当前管理员、有效登录与 Agent 能力，不读取原文件或执行回收。异步预检得到完整计划后才能明确确认；相同登录和幂等键重试不刷新期限，换命令冲突，重新登录不能使用旧意图和确认令牌。
- 按既有十五分钟规划、五分钟 Ready 与十五分钟执行窗口衔接；确认版本/到期、租约、Job/Outbox/审计的原子持久化由仓储契约约束，实际 PG 实现仍待。接口注释明确所有写入者及跨容器同宿主目录必须共享排他保护，不能用此接口或内存仓储冒充数据库保护。
- 原计划含可变属性数组；在最后权限复核前深复制完整计划、保留字节/零值/纳秒与 uint64 身份，随后绑定规范 JSON。重复字段、未知字段、非规范序列化或任意请求/计划/执行字段篡改均拒绝。
- 分派先观察原执行 ID；没有回执且未记录 Root 开始、授权/期限有效、仓储成功获取保护后才 Apply。规划/写入 RPC 中每六秒复核租约、登录和实时管理员，135 秒总调用上限覆盖现有 120 秒 RPC。响应丢失、调用被取消或已有开始标记后，只观察/Discard 原执行，不再 Apply。
- 已观察到 Trashed 且当前绑定有效才映射成功；目标不再匹配为 Superseded，已 Restored 同样为 Superseded/ALREADY_RESTORED，不能算一次新回收成功。身份服务临时不可用不抹掉已取得的原回执；无回执不能推断零修改，Unknown 保留保护。
- 保存完整回执及独立 MAC，列表投影的 RootState、源留存/恢复、历史与当前可用性均须与原回执一致。Unknown 的两个未证明源字段保持 null。当前绑定/历史可用性可更新，但明确处置不能改变原状态、源事实、历史摘要及既有验证事实。
- 当前管理员明确处置前重新检查授权，再对原执行做 Discard，取得相容回执后再次检查权限并交仓储原子处置；不隐式恢复或彻底删除。业务层没有调用 Restore 的捷径，恢复必须随后实现独立意图/确认/执行任务和来源绑定。

SDK 新增仅用于 Plan 的明确拒绝分类，严格匹配 gRPC 状态与安全错误码：原文件变化、不支持的文件/扩展属性、受保护目标、实例变化和属性上限。网络、容量、超时及不匹配的状态组合仍是暂时/不确定故障；同一错误发生在 Apply 时不据此推断未写入。
