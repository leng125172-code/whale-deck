# 通知与消息中心

本功能按 P0-07/P2-12/P4-06 分阶段实施；站内收件箱是外部路由/投递的持久化基础，不取消后续 Email/Webhook/钉钉/企业微信/飞书等渠道。当前开发中的第一阶段不是全部通知功能完成。

## 站内事件与权限

- 不使用活动告警数量假装未读数量。新增 typed `notification_events` 与每个 Authentik subject 独立的 `notification_read_states`，不复制密码或用户资料。
- 事件在同一次 EF SaveChanges 内与告警历史/Job 终态同事务保存，失败一起回滚。SourceKey 唯一：告警历史 UUID；Job UUID + 终态。一次重试不会重复生成同一消息。既有历史不伪造补投，通知从本版本开始；原告警历史仍可查询。
- 告警触发、严重变化、恢复、静默到期产生管理员广播；有效静默期间不投递。人类发起的任务终态只通知原发起者，system 任务通知管理员。每个管理员独立已读；降权后不可再查询管理员广播。普通用户只看本人消息且不返回管理员资源链接。
- 不复制请求/结果 JSON、错误原文、凭据、用户输入或资源名称；内容使用固定代码和模板，关联源 ID 仅对可见消息返回。
- 事件默认有效 180 天，读状态随事件级联清理。消息为不可变事实，API 只允许修改自己的读状态；不支持凭 ID 操作别人消息。

## API 与前端

- `GET /api/v1/notifications?take=50&before=<sequence>&status=all|unread&kind=all|Alert|Job`，稳定顺序分页，上限 100。
- `GET /api/v1/notifications/summary`，返回个人未读/总数和 snapshotSequence。
- `POST /api/v1/notifications/{id}/read-state` `{isRead:true|false}`；同一 subject 串行锁、重复操作幂等。
- `POST /api/v1/notifications/read-all` `{throughSequence:<snapshot>}`；只标记本人当时可见的旧消息，新消息保留未读。未来/不再可见的快照范围拒绝。
- Cookie 写请求继续全局防伪 Token/Origin；修改同事务审计，不记录消息正文。
- 全部已读每次最多处理 1000 条并返回 hasMore，界面用相同快照继续批次；取消/退出时保留已完成批次，不把部分结果冒称全部完成。
- 已接前端（尚未上线）：普通用户也可打开顶部个人收件箱，真实未读徽标不再使用活动告警数量。管理员另有活动告警页签；已读/未读筛选、告警/任务类别、逐条读/未读、快照分批全部已读、更多分页、加载/错误/空态。退出/降权清空，迟到响应不重新填入私有消息，摘要轮询仅页面可见时执行且不重叠；摘要失败显示不可用标记，不假装未读为零。
- 消息清理独立于 Agent，每分钟最多删除 1000 条过期事件，读状态级联删除；多 Worker 通过事务级锁避免重复扫描。批次失败一分钟后重试，不输出消息正文。
- 公共 HTTP 客户端组合外部取消和 15 秒截止时间，CSRF 获取也可取消；失败释放计时器。抽屉关闭可终止后续已读批次，已提交的批次不自动回退。
