## 2. 产品定位与边界

WhaleDeck 是 Precision 7920 工作站的内部协同与运维控制面，不以替代所有专业运维工具为目标。它负责把身份、工作站状态、容器、数据库、应用、用户同步和审计收拢到一个入口。

### 2.1 已确认边界

- 使用 IP 地址访问，不依赖域名。
- 当前保持 HTTP，不启用 HTTPS；未来如跨越受信任局域网再重新评估。
- 内网地址为 `192.168.22.19`，固定 IP、无外网，允许访问 WhaleDeck 和容器入口。
- 外网局域网地址为 `192.168.100.13`，用于本机下载及局域网访问，也允许登录 WhaleDeck。
- 只有统一网关发布宿主机端口；API、Worker、Agent、数据库、缓存和 Authentik 不直接发布端口。
- Authentik 是用户名、密码、MFA、用户资料、账户状态和用户组的唯一事实来源。
- WhaleDeck 不保存本地密码，不复制 Authentik 用户资料表。
- 只有 Authentik 中配置为“管理员组”的成员拥有管理权限；其他已登录用户只能查看首页仪表盘和使用个人门户入口。
- WhaleDeck API 与 Worker 容器不挂载 `/var/run/docker.sock`。
- 容器管理和宿主机管理通过单独的 `WhaleDeck.Agent` 完成。
- WhaleDeck 核心容器属于受保护资源，普通容器操作不能停止、删除或重建它们；自身维护必须走专用维护流程。
- 数据库运行数据放在 NVMe，备份写入 HDD；HDD 备份不等同异地灾备。
- 容器和应用日志必须有界，禁止无上限文件日志及高频信息日志。
- 工作站每周日 20:00 安装普通系统更新，不自动重启。
- 主机指标每 6 秒采集一次，原始或可查询历史保留 14 天。
- 只有显式设置 `autoupdate=true` 标签的容器才允许自动更新镜像。
- 高风险操作不引入审批流，由管理员完成二次确认后执行并记录审计。

### 2.2 暂不作为首期目标

- Kubernetes、Docker Swarm 和多节点集群编排。
- 公网暴露、域名管理和证书自动签发。
- 完整替代 Portainer、pgAdmin、SSMS、MongoDB Compass 等专业工具。
- 任意宿主机命令执行和无约束的 Web 终端。
- 容器终端、数据库恢复、文件管理、防火墙和网络写操作只预留设计，不在当前开发阶段实现。
- 外部告警渠道只预留扩展点，不在当前开发阶段实现。
- GitLab 部署、用户同步与 SSO 集成在 WhaleDeck 核心开发完成后再实施。

## 3. 总体架构

```text
浏览器
  │
  ▼
宿主机稳定入口（systemd + Nginx/Caddy）
  ├── 正常状态 ──► WhaleDeck Gateway 容器
  │                 ├── Vue 静态资源
  │                 ├── /api/*  ──► WhaleDeck.Api
  │                 └── /auth/* ──► Authentik
  └── Docker 维护状态 ──► 本地维护加载页与只读状态

WhaleDeck.Api
  ├── Authentik OIDC / BFF 会话
  ├── PostgreSQL：设置、权限映射、审计、任务历史
  ├── Valkey：缓存、短期状态、分布式锁、任务进度
  ├── WhaleDeck.Worker：后台同步、采集、计划任务
  └── /run/whaledeck/agent.sock ──► WhaleDeck.Agent

WhaleDeck.Agent（宿主机 systemd 服务）
  ├── Docker Engine API
  ├── systemd / journal
  ├── /proc / /sys
  ├── 网络、磁盘、进程与主机信息
  └── 经过白名单的宿主机操作
```

### 3.1 组件职责

| 组件 | 主要职责 | 禁止事项 |
| --- | --- | --- |
| 宿主机稳定入口 | 持有唯一访问端口、代理容器化 Gateway、Docker 维护时提供最小加载页 | 不提供业务管理 API，不保存用户凭据 |
| Gateway | 容器化前端入口、Vue 静态资源、反向代理、安全响应头 | 不直接执行宿主机操作 |
| Vue 前端 | 展示、交互、确认、任务进度、错误恢复 | 不保存 OIDC Token，不直接调用 Docker |
| WhaleDeck.Api | BFF、授权、业务用例、审计、Agent 调度 | 不直接挂 Docker Socket，不执行宿主机 Shell |
| WhaleDeck.Worker | 数据同步、周期采集、异步任务、告警计算 | 不直接获得宿主机 root 权限 |
| WhaleDeck.Agent | 主机采集、Docker 操作、受限 systemd 操作 | 不直接面向浏览器，不监听宿主机公网端口 |
| PostgreSQL | 持久化配置、审计和任务记录 | 不存 Authentik 密码或完整用户资料副本 |
| Valkey | 缓存、锁、短期任务状态 | 不作为唯一持久化来源 |

## 4. 用户角色与权限

用户与用户组全部来自 Authentik，WhaleDeck 首期只采用“管理员/普通用户”两级权限，不在本地独立维护用户、密码或多套角色。

| 角色 | 来源 | 权限范围 |
| --- | --- | --- |
| `Administrator` | Authentik 中被配置为管理员组的成员 | 查看全部页面；新增、删除、启动、停止、重启、安装、更新、备份以及平台设置等管理操作 |
| `User` | 其他已登录 Authentik 用户 | 仅查看首页仪表盘、使用并配置自己的门户入口；不显示容器、数据库、主机和平台管理导航 |

- 管理员组名称或组 ID 通过部署配置指定，不把固定组名写死在代码中。
- 后端必须对每个管理 API 再次校验管理员组，不能只依赖前端隐藏按钮或导航。
- 权限同时校验管理员身份、操作类型和资源保护策略；管理员也不能从普通容器列表破坏 WhaleDeck 核心容器。
- 更细的操作员、审计员或应用管理员角色只保留扩展能力，首期不实现。

### 5.4 容器管理

功能参考 Portainer 的容器、镜像、网络、存储卷和 Stack 分层，但所有写操作都必须经过 WhaleDeck 权限和审计。

#### Docker 总览

- `MVP` Docker Engine 在线状态、版本、API 版本、运行时和存储驱动。
- `MVP` 容器、镜像、网络、卷、Compose 项目数量。
- `MVP` 运行、停止、异常、重启中和健康检查失败数量。
- `P1` 镜像占用、可回收空间和 Docker 数据目录容量。
- `P1` Docker 事件时间线。

#### 容器列表与详情

- `MVP` 搜索、状态筛选、Compose 项目筛选、标签筛选。
- `MVP` 名称、镜像、状态、健康状态、启动时间、端口、网络。
- `MVP` 创建独立容器：镜像、名称、命令、环境变量、端口、挂载、网络、标签、重启策略、健康检查和 CPU/内存限制。
- `MVP` 从现有容器复制配置创建新容器；保存前展示配置差异和名称、端口、挂载冲突。
- `MVP` 启动、停止、重启；停止和重启需要二次确认。
- `MVP` 删除容器需要二次确认，并单独选择是否删除匿名卷；默认不删除数据卷和镜像。
- `MVP` 查看日志，支持时间、级别、关键字、尾部行数和实时追踪。
- `MVP` CPU、内存、网络和块 I/O 实时统计。
- `MVP` Inspect 信息只读展示，敏感环境变量默认脱敏。
- `MVP` WhaleDeck 核心容器标记为受保护，普通列表不提供停止、删除、重建和手动更新操作。
- `P1` 重建、更新镜像和导出诊断包。
- `P1` 查看挂载、网络、环境变量、标签、重启策略和健康检查。
- `P1` 批量启动、停止、重启和删除；批量操作前列出受影响资源并跳过受保护容器。
- `HOLD` 容器终端只预留权限与审计接口，当前阶段不实现。

#### 镜像

- `P1` 镜像列表、标签、摘要、大小、创建时间和引用容器。
- `P1` 从已批准 Registry 拉取镜像并显示进度。
- `P1` 检查镜像更新；只有带有 `autoupdate=true` 标签的容器允许进入自动更新任务。
- `P1` 未标记 `autoupdate=true` 的容器只提示新版本，不自动拉取、重建或替换。
- `P1` 受保护核心容器即使带有该标签也不进入普通自动更新任务，只允许走核心维护流程。
- `P1` 自动更新前保留当前镜像摘要和 Compose 配置，更新失败时自动回滚并生成审计记录。
- `P1` 管理员配置检查周期、维护时间段、允许的版本范围、失败重试次数和是否仅更新补丁版本。
- `P1` 同一 Compose 项目按依赖顺序更新；更新历史记录旧/新摘要、耗时、结果、回滚和关联任务。

- `MVP` 保存 Docker 设置后由 Agent 创建持久化维护任务、备份旧配置，再重启 Docker。

- `MVP` Docker 停止后宿主机 Agent 仍可工作并恢复 Docker，任务状态保存在宿主机，不依赖 API、PostgreSQL 或 Valkey 在线。
- `P1` 核心容器自身更新采用受控顺序或滚动切换，至少始终保留一个可服务实例；禁止在普通容器页面直接操作。

### 5.5 数据库与缓存平台

| 类型 | 实例/用途 |

#### 前端功能

- `MVP` 实例卡片：类型、版本、容器状态、健康状态、运行时间和存储路径。
- `MVP` NVMe 数据容量和 HDD 备份容量。
- `MVP` 连接数、数据库数量、慢查询/错误摘要和最近备份。
- `MVP` 启动、停止、重启数据库容器，停止与重启二次确认。
- `MVP` 按数据库类型创建和删除数据库/Schema，以及创建、禁用、删除账号或角色。
- `MVP` 分配数据库级权限、只读/读写权限，支持密码轮换和强制断开指定连接。
- `MVP` PostgreSQL/MariaDB/SQL Server 使用数据库与角色模型，MongoDB 使用数据库用户和角色，Valkey 使用 ACL；不强行伪装成完全相同的表单。

- `P1` 异地复制目标与复制状态；本机 HDD 仍不视为异地灾备。
- `HOLD` 数据库恢复只保留数据模型、任务类型和权限设计，当前阶段不提供页面或执行接口。
- `P1` 查看经过脱敏的连接信息；密码只允许重新生成或受控查看。
- `P1` 配置差异查看，不在第一版提供任意配置文件编辑器。
- `P2` 跳转专用管理工具，不在 WhaleDeck 内实现完整 SQL 工作台。

#### 后端约束

- 数据库端口不发布到宿主机，只允许明确加入内部网络的应用连接。

- 新建应用账号遵循最小权限，不允许通过普通界面授予服务器超级管理员权限。
- 密码明文只存在于创建/轮换过程，响应后不再回显；持久化引用 Secret，不把密码写入业务表和审计详情。
- WhaleDeck 通过 Agent 调用 `database-platform` 已有检查与备份脚本。
- 备份任务必须异步执行、可查询进度、可取消且产生审计记录。
- 恢复脚本当前不从 WhaleDeck 暴露；以后启用时只允许管理员操作并要求二次确认。
- 密钥、数据库密码和 SQL Server 产品密钥不得写入日志、数据库审计详情或 Git。

### 6.2 WhaleDeck.Agent

建议作为独立 .NET Worker 安装为宿主机 systemd 服务，通过 Unix Socket 提供内部 gRPC 接口。

#### 只读能力

- 主机、操作系统、内核、CPU、内存、负载和运行时间。
- 网卡、地址、路由、流量和链路状态。
- 磁盘、文件系统、挂载点、I/O 和 SMART 摘要。
- systemd 服务与 timer 状态。
- journald 查询。
- Docker Engine 信息、容器、镜像、网络、卷、事件、统计和日志。
- `database-platform` 检查脚本结果。

#### 写操作

- 创建、复制、启动、停止、重启和删除非受保护容器。
- 拉取镜像和受控 Compose 重部署。
- 执行批准的数据库备份脚本；恢复 RPC 仅预留契约，不注册为可调用能力。
- 校验、备份并应用 Docker 配置，重启 Docker 后等待受保护容器恢复健康。
- 执行普通系统更新。
- 执行管理员确认的主机重启，并在重启前持久化维护状态。
- 通过固定参数执行批准的配置仓库状态检查、快照、提交和推送流程。
- 编排 WhaleDeck 核心容器的受控更新、健康检查和回滚。
- 启动、停止或重启白名单内 systemd 服务。
- 写操作必须携带用户、任务 ID、资源 ID、动作、幂等键和授权声明。

#### Agent 安全边界

- Unix Socket 位于 `/run/whaledeck/agent.sock`，不开放 TCP 端口。
- 仅 WhaleDeck API 所属组可连接。
- 每个 RPC 使用明确 DTO，不提供任意 Shell 字符串参数。
- 路径使用服务器端注册的资源 ID，不接受任意绝对路径。
- 容器按标签和保护策略校验；核心容器默认受保护。
- Docker 服务和 WhaleDeck 自身相关操作使用更高权限等级；网络写操作当前不注册。
- Agent 记录结构化审计，但避免重复写入高频指标日志。

### 6.3 WhaleDeck.Worker

- `MVP` Agent 心跳和能力同步。
- `MVP` 每 6 秒采集指标，按查询粒度汇总和降采样，并清理超过 14 天的数据。
- `MVP` Docker 事件订阅和容器状态缓存。
- `MVP` 轩辕热门应用抓取与缓存。
- `MVP` 异步任务调度、租约、超时、取消和失败重试。
- `MVP` 备份结果同步和告警生成。
- `MVP` 以最长 2 小时缓存重新校验 Authentik 管理员组；权限下降后拒绝后续管理请求，并取消该用户尚未开始的管理任务。
- `P1` Authentik 管理员组状态同步。
- `HOLD` GitLab 用户组同步任务在核心开发完成前不注册。
- `P1` 镜像更新检查和系统更新检查。
- `P1` 执行类型化计划任务、自动更新窗口和资源冲突控制。
- `P1` 配置仓库状态检查和 WhaleDeck 版本检查。
- `P1` 页面通知、告警去重与恢复通知。
- `HOLD` 外部通知投递器只保留接口，不注册邮件、Webhook 或钉钉实现。

### 6.4 数据持久化建议

#### PostgreSQL

- `AuditEvent`：不可变审计事件。
- `PlatformSetting`：非敏感动态设置。
- `OperationJob`：异步任务、进度、结果和幂等键。
- `ScheduledTask`、`ScheduledTaskRun`：类型化计划、并发规则和执行历史。
- `ManagedResource`：资源 ID、类型、标签和保护策略。
- `ApplicationInstallation`：模板、版本、关联资源、配置摘要和更新历史。
- `UserPortalItem`：以 Authentik Subject 为所有者的个人门户配置。
- `MetricSample`/`MetricRollup`：历史指标或其聚合值。
- `AlertRule`、`AlertEvent`：告警规则、触发和恢复。
- `RoleMapping`：Authentik 组到平台角色映射。
- `ExternalSyncRun`：Authentik/GitLab 同步历史。
- `BackupRecord`：备份文件、校验、大小、保留期和恢复记录。
- `ConfigSnapshot`、`ConfigSyncRun`：配置快照、差异摘要和 Git 同步结果，不存储 Secret 内容。

不建立本地密码表，不复制 Authentik 的姓名、邮箱等完整用户资料。

#### Valkey

- 概览快照和热门应用缓存。
- Agent 心跳和容器短期状态。
- 分布式锁、幂等键和任务进度。
- SSE/WebSocket 通知的临时状态。
- 频率限制和短期权限缓存。

Valkey 数据丢失后系统必须能够从 PostgreSQL、Agent 和外部服务恢复。

## 8. 操作安全等级

| 等级 | 示例 | 前端要求 | 后端要求 |
| --- | --- | --- | --- |
| L0 只读 | 查看允许的仪表盘与门户 | 无确认 | 所有已登录用户可用；敏感信息仍受权限限制 |
| L1 管理 | 新增门户、启动普通容器、立即备份 | 明确操作结果 | 管理操作仅管理员；个人门户由本人管理 |
| L2 有中断 | 停止/重启容器、更新应用 | 二次确认并展示影响 | 管理员 + 审计 + 资源保护校验 |
| L3 数据/主机风险 | 删除资源、保存 Docker 设置并重启服务 | 二次确认、展示影响和回退方案 | 管理员 + 独占锁 + Agent 白名单 + 完整审计 |

不引入多人审批流或单独审批角色。受保护资源至少包括：WhaleDeck Gateway/API/Worker、WhaleDeck Agent、宿主机稳定入口、Authentik、PostgreSQL、Valkey 和关键数据库实例。

## 9. 非功能要求

### 安全

- 默认拒绝，显式授权。
- 所有写操作服务端再次校验，不能依赖前端隐藏按钮。
- 防止 CSRF、开放重定向、越权访问和资源 ID 猜测。
- 敏感字段默认脱敏，不写日志，不进入错误详情。
- API、Agent、数据库和缓存不直接发布宿主机端口。

### 可用性

- Agent 离线时前端进入明确的只读降级状态。
- 外部依赖失败不能阻止查看最近一次有效快照。
- 长任务可恢复、可查询且不会因浏览器关闭而中断。
- Docker 停止后宿主机 Agent 仍可工作并恢复 Docker。
- Docker 重启时，已打开页面保持维护加载态；宿主机稳定入口保证刷新或新访问仍能看到启动进度，而不是连接失败。
- `live-restore` 用于尽量保持现有容器运行，但不能替代健康检查、受控恢复和失败回滚。

### 性能

- 概览 API 目标响应时间小于 500ms，使用 Valkey 快照避免现场串行探测。
- 高频指标按 6 秒采样，先在 Agent 聚合再批量写入；只保留 14 天，不把每次采样写入应用日志。
- 容器日志和 journald 查询必须限制时间、行数和返回大小。

### 日志

- 应用只向 stdout/stderr 输出结构化 JSON。
- 正常请求低于错误级别，避免重复发生日志打满磁盘事故。
- Docker 使用有界 `local` 日志驱动和轮转。
- 审计事件与运行日志分离。

### 前端体验

- 字号基线：指标总量 28–32px；模块标题 16px；卡片标题 14px；正文/键值 13px；辅助文字 12px。
- 颜色不是唯一状态表达，必须同时提供文字或图标语义。
- 危险操作统一确认、结果提示和任务入口。
- 支持键盘焦点、可访问名称和减少动画。
- 小屏优先展示状态和主要操作，次要信息进入详情页。
