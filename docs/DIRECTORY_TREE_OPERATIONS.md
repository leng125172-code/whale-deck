## 清单引擎

`deploy/host/whaledeck-file-tree.py`只接受登记根、非空相对目录和原版本。继续使用原driver的openat2 BENEATH/NO_SYMLINKS/NO_MAGICLINKS/NO_XDEV；逐项拒绝保护文件/目录、符号链接、特殊设备和多硬链接文件。遇到不支持项拒绝整个计划，不静默省略后宣称复制成功。

上限：10,000项（包含所选目录）、32层、总数据16GiB、编码清单16MiB、单次扫描默认300秒/最高600秒。读取逐块响应取消，目录成员收集在排序前限量；UTF-8/控制字符/路径长度及实际JSON编码字节预算均验证。不将完整清单塞进现有64KiB helper帧。

固定UTF-8兄弟排序、目录前序，逐文件完整SHA256、完整身份/版本/类型/长度及根策略摘要生成域分离清单Hash；前后目录与路径绑定、读取中源元数据及全树最后策略重新验证。**清单是乐观逐项快照，不是原子文件系统快照**；源在最后校验之后仍可能被外部修改，不能据此保证任意时间点的一致性备份。

内部`_scan_descriptor`仅供可信执行引擎重新散列私有临时树，不注册私有路径、不开任意FD/RPC，也不绕过成员保护和挂载检查。

## 复制执行与恢复

`deploy/host/whaledeck-tree-copies.py`提供内部plan/copy/lookup/discard。小型计划只有原命令、完整清单Hash、数量/字节、目标父目录身份和两端策略Hash；根私有回执上限32KiB。清单在内存中有界重新生成，不把整个树或正文放进回执/日志/响应。

- 根所有/0700状态目录、0600单链接回执与锁；每操作内核锁及与旧写入相同的namespace锁。固定操作ID/owner/原计划绑定；幂等恢复不补做物理发布。
- 目标必须不存在，支持不同已登记根和真实不同设备。源/目标词法关系及真实清单目录inode检查同时拒绝重叠，包括不同根的bind别名；禁止覆盖已有文件/目录/链接。
- 原源清单完全一致后，目标文件系统内私有目录先完整复制；逐文件源版本/长度/全SHA，目标根登记UID/GID、原普通权限/mtime，去掉setuid/setgid/sticky等特殊位，目录自底向上完成。重新读源全树和目标全树，核对成员/正文/模式/归属/mtime，再记录完整目标树身份Hash。
- 发布前再验证策略、父目录绑定与完整临时树；`renameat2(RENAME_NOREPLACE)`原子发布并fsync两个父目录。目标被抢占时保留外部对象，不覆盖、不清掉它。
- Preparing→Staging→Ready→Publishing→Completed；查验只按实际相同inode/成员/元数据/全字节证明结果，发布后响应丢失可找回原结果，不重跑复制或发布。
- 原操作私有临时树仍在可证明未完成发布时为Aborted；目标/策略/身份不明或发布后被移走为Unknown。保留私有部分副本并明确`partialRetained`，不递归删除、不自动回滚、不动源目录。此保留**不是HDD备份**，不能代替目录回收所需HDD设计。
- discard保存原计划取消栅栏，源变化/根撤权后仍能阻止迟到copy；不把已经Completed改成Canceled。Completed表示原操作历史，不暗示用户之后没有修改目标文件。

目录移动**不能把整个源祖先直接rename进私有目录**：校验后新插入的保护文件也会被搬走。后续须逐叶校验保留、只移除已证明为空的目录；出现未知/新成员保留原对象，明确部分结果，不能声称全树原子移动。ZIP/TAR必须另有路径/类型/压缩比/数量/展开容量/链接预算，不能接受任意解压命令。
